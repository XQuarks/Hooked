# 04 · 重制方案与关键取舍

> **概述**：给出重制版的完整技术方案：渲染选型与取舍、3D 场景构成、玩法与 3D 的映射规则、数值重做、工程架构、分阶段实施与验收。所有取舍都附「为什么不选另一条路」。
> **状态**：已完成，作为实现依据（`rebuild/` 目录）。
> **读者**：实现者、评审者。
> **关联**：`01` 结构基线、`02` 问题清单、`03` 增删清单。

---

## 1. 目标 / 非目标

**目标**

1. 竖屏、单手可玩，核心四阶段循环与原版一致。
2. 场景具备**真实光照感**：方向光、雾、焦散、体积光、Bloom、水下色彩衰减。
3. 保留原版的叙事资产（鱼种、角色、剧情、漂流瓶），并让它在新底座上继续成立。
4. 交付一个**可运行、可离线打开**的结果（单文件 HTML），无外部请求。

**非目标**

- 不做自由视角 3D（会破坏竖屏可玩性与操作一致性）。
- 不做联网、排行榜、内购。
- 不追求写实画风（写实鱼 + 卡通叙事会撕裂），走**低多边形 + 绘画感光照**。
- 不导入任何外部模型/贴图（保证单文件与零版权风险）。

## 2. 渲染选型：三条路的取舍

| 方案 | 光影视感 | 竖屏适配 | 资源成本 | 单文件可行 | 风险 |
|---|---|---|---|---|---|
| **A. three.js 3D（选用）** | ★★★★★ 真实方向光/雾/焦散/Bloom | 固定机位侧视，天然适配 | 代码多，包体 +~650KB | ✅（打包内联） | WebGL 兼容、移动端 GPU |
| B. Canvas 2D 强化（多层视差 + 屏幕空间光） | ★★★☆ 需要大量手绘渐变伪装 | 最稳 | 中 | ✅ | 上限低，「光影」仍是画出来的 |
| C. PixiJS 2D + 滤镜 | ★★★★ 有正常贴图 + 滤镜链 | 稳 | 需要贴图资源 | ⚠️ 贴图需 base64 | 写法与旧版近似，收益不明显 |
| D. 3D 场景 + 2D 精灵鱼（billboard） | ★★★★ | 稳 | 中 | ✅ | 鱼失去体积感，与「精美 3D」定位不符 |

**选 A**，并且做一个关键约束：**相机永远朝向 −Z、只沿 Y 平移**（等价于「3D 化的 2.5D」）。这样：

- 玩家看到的仍然是「左右移动 + 上下深度」的经典竖屏构图，学习成本为零；
- 碰撞可以继续用 2D 圆判定，瞄准不会因为透视而变难；
- 但仍然获得真实的光照、遮挡、雾衰减、阴影与景深层次。

> 取舍理由：纯 3D 自由视角会让「点鱼开枪」变成一场透视折磨；纯 2D 又达不到「带光影的精美 3D 场景」。**2.5D 固定机位是唯一同时满足两者的解。**

## 3. 3D 场景构成（性能预算内）

### 3.1 空间与相机

```
世界单位：1 unit = 1 米
水面     y = 0
海底     y = −(地图最大深度)   bay: −400   ice: −600
玩法平面  z = 0（碰撞只在 x/y 上算）
鱼纵深    z ∈ [−2.2, +2.2]（只影响视觉遮挡与大小）
相机      PerspectiveCamera(52°)，位于 (0, camY + 1.8, 14)，看向 (0, camY, 0)
可视范围  高约 13.6m、宽约 7.7m（竖屏 9:16）⇒ 单屏约 10~14 条鱼
```

### 3.2 光照方案（重点）

| 元素 | 实现 | 为什么这么做 |
|---|---|---|
| 主光 | `DirectionalLight` 从水面上方斜射，颜色随深度带从暖白 → 青 → 深蓝 | 一个光源就能建立「光从上面来」的世界观 |
| 环境光 | `HemisphereLight`（上=水色，下=海床反射色） | 补暗部，避免死黑 |
| 焦散 | 两张 canvas 生成的焦散贴图，以不同速度滚动，叠加在海床/礁石的 `emissiveMap` 上 | 比真实光子映射便宜 3 个数量级，视觉收益 80% |
| 体积光 | 9 张竖直加性平面（径向渐变纹理），缓慢摆动，随深度衰减 | 真体积雾需要 raymarch，移动端不可行；平面伪造足够 |
| 雾 | `FogExp2`，颜色按深度带插值，密度随深度上升（0.018 → 0.055） | 雾同时承担「深度压迫感」与「远处剔除」 |
| 头灯 | 绑定在鱼钩上的 `PointLight`（仅冰海/深渊带开启） | 让「黑暗」成为可被玩家操作的空间 |
| 水面 | 自定义 ShaderMaterial：从水下看是明亮的「Snell 窗」+ 波纹；从水上看到波光 | 这是「水下感」最强的一眼信号 |
| 后处理 | `UnrealBloomPass`（强度 0.28~0.45）+ 轻微暗角 | 发光鱼、鱼钩、爆炸的价值感来源 |
| 阴影 | 高画质才开：`DirectionalLight` 1024 阴影图，仅海底道具与近底鱼投射 | 水下阴影收益低于成本，默认关 |

### 3.3 深度带（Biome）设计

| # | 名称 | 深度（bay） | 光照 | 雾色 | 道具 | 主导鱼行为 |
|---|---|---|---|---|---|---|
| 1 | 阳光浅滩 | 0–80m | 强、暖，光柱密集 | 青绿 | 沙丘、海草、浮标 | cruise / school |
| 2 | 珊瑚林 | 80–180m | 中，斑驳 | 蓝绿 | 珊瑚、礁石、鱼群 | school / dart |
| 3 | 蓝洞 | 180–300m | 弱，顶光收束 | 深蓝 | 石柱、沉积物 | cruise / hunt |
| 4 | 断崖 | 300–400m | 很弱 | 近黑蓝 | 悬崖、沉船、锚链 | dart / hunt |
| 5 | 深渊 | 400m+（ice） | 无自然光，仅头灯 | 黑 | 热泉、巨骨 | hunt / rare |

冰海使用同一套带结构，但整体色温偏冷、极光作为唯一环境光、5 带对应「浮冰 / 冰柱 / 沉船 / 热泉 / 王座」。

### 3.4 对象与 draw call 预算

| 对象 | 数量上限 | 实现 |
|---|---:|---|
| 鱼 | 28 | 每鱼 2 个 mesh（合并体 + 尾巴），共享几何缓存 |
| 海床 | 1 | 单块 64×64 段位移平面，顶点色 |
| 礁石/珊瑚/海草 | 60 | `InstancedMesh`（按类型 3~4 个实例组） |
| 体积光 | 9 | 单几何 + 单材质，实例化颜色 |
| 粒子（浮游/气泡） | 400 | 单个 `Points`，着色器内做循环动画 |
| 鱼群（远景剪影） | 60 | 单个 `InstancedMesh` |
| 水面/天空 | 2 | 单平面 + 单球 |

**总计 < 120 draw call**，中端手机可稳 45fps（中画质、DPR 1.5）。

### 3.5 画质分级

| 档位 | DPR | Bloom | 阴影 | 体积光 | 粒子 | 抗锯齿 |
|---|---|---|---|---|---|---|
| 低 | 1.0 | 关 | 关 | 4 条 | 120 | 关 |
| 中 | 1.5 | 0.3 | 关 | 7 条 | 260 | 开 |
| 高 | 2.0 | 0.42 | 1024 | 9 条 | 400 | 开 + SMAA 关闭（FXAA 由 CSS 替代） |

## 4. 玩法与 3D 的映射规则

| 原版（2D px） | 重制（3D m） | 说明 |
|---|---|---|
| `PPM = 12 px/m` | 1 unit = 1 m | 所有深度数值直接沿用 |
| 画布 420×720 | 相机视野 7.7×13.6 m | 单屏「看到」的深度≈13m，与原版 60m 不同 → **下潜速度同步压缩** |
| 下潜速度 `230 + y×0.035` px/s | `9 + depth×0.012` m/s | 400m 约 27s（原 14s）。重制更慢，因为要「看风景」，用 biome 变化补偿 |
| 收线速度 420~780 px/s | 12~20 m/s | 400m 约 26s（原 10s）；用「连钩」节奏补偿 |
| 重力 720 px/s² | 9.8 m/s²（射击段用 12 提升手感） | 鱼飞 40~90m 高，等效原版的「高空/平流层/太空」分层 |
| 判定半径 `size×0.85+7` px | `size×0.9 + 0.35` m | 略放大，补偿 3D 难度 |
| 鱼速 25~130 px/s | 0.8~4.2 m/s | 换算比例 ≈ 0.03 |
| 点击判定半径 38~74 px | 1.1~2.1 m | 仍用「点到平面 z=0」的射线投影，不做真 3D 瞄准 |

> **关键取舍**：三维化之后**主动把节奏放慢 30~40%**。因为 3D 场景的信息量是 2D 的 3 倍，如果沿用原速，玩家只会看到一片糊。慢下来，光影和 biome 才有意义，这也是「重制」而非「换皮」的核心。

## 5. 数值重做

### 5.1 经济

| 项 | 原版 | 重制 | 理由 |
|---|---:|---:|---|
| 单条鱼均价 | $15（bay） | $22（bay，+47%） | 缩短前期空窗 |
| 冰海均价 | $52 | $78 | 保持 3.5 倍梯度 |
| 升级总需求 | $121,750 | **$41,600** | 压缩到 55 局以内全满 |
| 皇冠 | $20,000 | **删除** | 极端价格无设计价值 |
| 水母罚款 | 固定 $20/$40 | `max(20, 本局毛收入×12%)` | 让负反馈随阶段生效 |
| 连杀 | 无 | ×1.0 → ×2.5 | 技巧变现 |
| 终局奖励 | $5,000 | $5,000 + 专属帽 | 保留 |

### 5.2 节奏

| 指标 | 原版 | 重制 | 说明 |
|---|---:|---:|---|
| 一局时长 | ~38s | ~70s | 下潜 27s + 收线 26s + 射击 15s |
| 到冰海 | ~18 局 | ~10 局 | 前置门槛降低 |
| 通关 | 20~30 局 | ~22 局 | 基本持平，但每局更「满」 |
| 全满 | 100~150 局 | **45~60 局** | 目标 |

### 5.3 鱼行为参数

| 行为 | 用于 | 规则 |
|---|---|---|
| `cruise` | 大多数鱼 | 匀速巡游，碰壁折返（原版行为） |
| `dart` | 旗鱼、冰鱼、小鲨鱼 | 每 1.6~3s 冲刺 0.6s，速度 ×2.6，冲刺前有 0.25s 摆尾预警 |
| `school` | 沙丁、鳕鱼、黄鱼 | 以 4~7 条为一组生成，组内共享方向与相位偏移 |
| `hunt` | 鮟鱇、睡鲨、海鳗 | 与鱼钩纵向距离 < 7m 时，横向朝鱼钩缓慢靠近（0.9 m/s），制造「躲不掉」的压力 |

`hunt` 是本版新增的**唯一对抗性行为**：它让「下潜躲鱼」从静态障碍变成会追你的活物。

## 6. 工程架构

```
rebuild/
├─ index.html
├─ package.json / tsconfig / vite.config.ts
└─ src/
   ├─ main.tsx
   ├─ App.tsx                 页面状态机、剧情队列、Overlays 装配
   ├─ game/
   │  ├─ data.ts              鱼/地图/深度带/升级/武器/帽子/瓶子
   │  ├─ state.ts             存档 v2 + v1 迁移 + 派生值
   │  ├─ story.ts             事件表（精简到 14 条）+ 角色 + 漫画
   │  ├─ audio.ts             WebAudio 合成音效（沿用原版配方，扩 4 个）
   │  └─ engine.ts            玩法状态机 + 相机 + 输入 + 结算
   ├─ three/
   │  ├─ Stage.ts             renderer/scene/camera/灯光/后处理/画质档
   │  ├─ water.ts             水面 shader + 天空球 + 体积光
   │  ├─ terrain.ts           海床位移 + 焦散贴图 + 道具实例化
   │  ├─ fish.ts              程序化鱼几何（10 形体）+ 材质缓存 + 行为
   │  ├─ fx.ts                粒子/气泡/爆炸/命中环/飘字（世界内）
   │  └─ thumbs.ts            离屏渲染器 → 鱼缩略图 dataURL 缓存
   ├─ ui/
   │  ├─ Hud.tsx              深度/钩数/预估收益/连杀/过热/紧急收线
   │  ├─ Title.tsx            标题页（3D 场景做背景）
   │  ├─ Result.tsx           结算
   │  ├─ Phone.tsx            手机壳 + 8 个 APP 路由
   │  ├─ apps/*.tsx           短信/剧情、鱼鉴、渔具、枪铺、航线、帽子、档案、设置
   │  └─ Story.tsx            来电/漫画/公告/漂流瓶
   └─ styles.css
```

**边界原则**（沿用原版最健康的一处设计）：

- `three/*` 不知道 React；
- `game/engine.ts` 只依赖 `three/*` 与 `game/*`，通过回调 `onEnd(result)` 把结果交给 React；
- `ui/*` 只读 `SaveState`，通过 `update(fn)` 写；不直接碰 three。

## 8. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 移动端 GPU 跑不动 Bloom + 体积光 | 中 | 高 | 三档画质；自动降档（连续 2s < 40fps 降一档） |
| WebGL 不可用（老设备/远程桌面） | 低 | 高 | 启动检测 `WebGL2`，失败显示明确提示与静态封面 |
| 程序化鱼「千鱼一面」 | 中 | 中 | 10 形体 × 颜色/体型/发光/特殊部件（角、须、牙）参数化 |
| 3D 让瞄准变难 | 中 | 高 | 判定用 z=0 平面投影 + 判定半径放大 20% + 命中吸附（最近目标 0.6m 内自动修正） |
| 单文件体积过大 | 中 | 中 | three 按需引入（不引 examples 全量）；gzip 后 ~450KB，可接受 |
| 节奏变慢导致「闷」 | 中 | 中 | 下潜段用 biome 切换、鱼群、光束做视觉事件；每 100m 弹出带名 |
| 改坏原版手感 | 中 | 高 | 02 §4 的三条底线做成回归检查项 |
