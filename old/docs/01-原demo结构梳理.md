## 2. 坐标与空间体系

```
逻辑画布  420 × 720（竖屏 7:12），DPR 上限 2，等比缩放填满容器
像素/米   PPM = 12
世界坐标  y 向下为正：水面 y = 0，阳光湾底 y = 400×12 = 4800px，冰海底 y = 600×12 = 7200px
相机      camY：屏幕 y = 世界 y − camY
视野高度  720px = 60 米
```

- 主角永远在 x 轴移动，鱼也在 x 轴水平巡游，碰撞退化为 **2D 圆-圆**。
- 相机在四个阶段有四种跟随策略（下潜看下方、收线看下方 62%、射击沿最高鱼、待机回水面）。
- 背景用「深度取色」：`waterColor(d)` 按深度在 `wTop → wBot` 之间做 0.8 次幂插值，`darkAt(d)` 再做一层黑幕；冰海额外用「32px 小 canvas + destination-out 挖洞」实现头灯。

## 3. 玩法状态机

`engine.ts` 的 `Phase` 是全局唯一真源：

```
                    startTrip()
   idle ──────────────────────────────► descent
     ▲                                    │  撞到鱼(无锯) 或 到底
     │                                    ▼
     │                                  turn (0.55s 定身，镜头下压)
     │                                    │
     │                                    ▼
     │                                 ascent ──► 到达 y ≤ 0
     │                                    │            │
     │  finish()（空中无活鱼 1.2s 后）      │            ▼
     └────────────────────────────────────┴───────── shoot
```

| 阶段 | 玩家输入 | 系统行为 | 关键参数（源码值） |
|---|---|---|---|
| `descent` | 指针位置 / 方向键控制 x | 加速下坠、撞击判定、捡瓶、洋流 | 初始加速 900（水面上）/ 500；最大速度 `230 + y×0.035`，乘帽子移速 |
| `turn` | 无 | 定身 0.55s，镜头从 30% 移到 62% | 咬钩与「鱼线到头」共用 |
| `ascent` | 控制 x 去撞鱼 | 自动上升；钩满后全速；电鳗触发甩鱼 | 起速 420 + y×0.03；满钩 780；加速度 900 |
| `shoot` | 点击 / 按住 | 鱼按抛物线飞出；命中掉血；未死则被打更高；镜头跟随最高鱼 | 重力 720；初速 vy −820~−1120；命中抬升 520+80×已中弹数；`slow` 0.6~1.0 缩放时间 |
| `idle` | 出海 / 手机 | 镜头回水面，船与钓竿待机动画 | — |

**几个容易被忽略的设计细节（重制时必须保住）**：

1. **下潜撞鱼 = 结束下潜**，这是整个游戏的风险核心：深 = 贵，但一次误撞就把你按在地上摩擦。玩家越贪，越容易翻车。
2. **收线阶段撞鱼 = 收益**，同一个碰撞在两个阶段意义相反，这是最优雅的一处设计。
3. **没打死的鱼会被打得更髙**（`lift = 520 + hits×80`，且 `vy` 重置为 −1100），于是「补枪」既是收益也是风险（飞太高会漂到太空，但不会掉钱）。
4. **鱼落回水面 = lost**（不计钱、计入 `lost`），扣的是机会成本而不是本金。
5. **水母罚款**是唯一会扣钱的负反馈，`value` 存负数（−20 / −40），帽子可减半。

## 5. 核心循环与时间预算

```
   ┌──────────────────────────────────────────────────────┐
   │                                                      │
   ▼                                                      │
 出海(35~45s) ──► 赚钱 ──► 手机升级(枪/线/钩/帽子) ──► 更深 ─┘
   │                                                      ▲
   └──► 剧情事件(SMS/来电/漫画/公告) ──► 解锁新地图 ───────┘
```

- **单局时长**：下潜 ~14s + 定身 0.55s + 收线 ~10s + 射击 ~10s + 结算 3s ≈ **38s**。
- **单局收益**（按源码数值估算）：早期 8~12 条浅水鱼 ≈ $40~80；中期 25 条 ≈ $300~600；冰海 40 条高价值鱼 ≈ $1500~3000。
- **每次出海后**：刷新热门鱼（售价 ×2）、可能推送「新纪录」到鱼博、结算漂流瓶。

## 7. 内容清单

### 7.1 鱼种（26）

| 地图 | 数量 | 深度跨度 | 单价跨度 | 血量 | 特殊 |
|---|---:|---|---|---|---|
| 阳光湾 | 14 | 0–400m | $3–$300 | 1–4 | 水母（罚）、金鱼（稀有）、灯笼鱼（发光） |

### 7.2 装备

- **5 项渔具升级**：鱼线（50→600m）、鱼钩容量（6→40）、电锯鱼饵（0→7 次）、头灯（70→270px）、防流鳍（0→90%）。
- **6 把枪**：手枪 / 双持 / 霰弹 / 冲锋枪 / 火箭筒 / 加特林，差异维度 = `伤害 × 弹丸数 × 射速 × 散布 × 溅射 × 是否连射`。
- **2 项枪改装**：瞄准镜（判定半径 +20~+56px）、子弹时间（0.6~1.0 倍速）。
- **7 顶帽子**：草帽（情怀）、鸭舌帽（+10% 下潜速度）、牛仔帽（+8% 收入）、厨师帽（罚款减半）、矿工帽（+40 灯）、皇冠（+25% 收入，$20000）、企鹅帽（剧情奖励，灯 +60 / 收入 +15%）。

## 8. 模块依赖关系

```
                    App.tsx
        ┌──────────────┼───────────────┐
        ▼              ▼               ▼
    Phone.tsx      Overlays.tsx    Engine（canvas）
        │              │               │
   ┌────┴────┐         │          ┌────┴─────┬──────────┐
   ▼         ▼         ▼          ▼          ▼          ▼
 Shops    Info/Social  story     data      draw      scenery
   │         │          │          │          │          │
   └─────────┴──────────┴──────────┴──────────┘          │
                    state.ts ◄───────────────────────────┘
                       │
                    sfx.ts
```

**耦合特征**：

- `Engine` 只依赖 `data / draw / scenery / sfx`，**不知道 React 的存在**，通过构造回调 `onEnd(TripResult)` 把结果抛回 React。这是这套代码最健康的一处边界。
- 但 `Engine` 也自己画 HUD（深度、钩数、横幅），导致「游戏内 UI」被劈成两套：Canvas HUD + React HUD，样式语言不统一（P2-6）。
- `story.ts` 的 `runStory()` 在每次 `update()` 后整体重跑，靠 `fired` 数组去重；条件函数直接读取整个 `SaveState`，属于「全量扫描式」事件系统。

## 9. 存档结构

```ts
SaveState {
  money, totalEarned, trips,
  map, unlocked[], 
  up{line,saw,hook,lamp,fin,scope,slowmo},
  guns[], gun, hats[], hat,
  caught{speciesId: count}, maxDepth{bay,ice},
  bestTrip, bestCatch, jellyHits, legend,
  bottles[], fired[], messages[], feed[], comics[],
  unread{}, readThreads{}, queue[],
  hotFish, sound
}
```

- 读取时与 `defaultSave()` 做浅合并 + `up` / `maxDepth` 深合并（缺字段不会崩）。
- **没有版本号、没有迁移函数、没有导出/导入**；改 key 就等于清档。
- `queue` 是演出队列，直接把「未播放的过场」存进存档——刷新页面不会丢剧情，这个设计值得保留。

## 10. 视觉表现手法清单（重制时的对照基线）

| 层次 | 手法 | 成本 |
|---|---|---|
| 天空 | 多段线性渐变 + 太阳/云/海鸥/灯塔/广告牌（bay）；星星/极光（ice） | 低 |
| 高空 | 110 个白点随高度变亮变大（穿云→太空的错觉） | 极低 |
| 水体 | 渐变 + 45 个视差浮游颗粒 + 光柱（5 条梯形） | 低 |
| 深度感 | 左侧刻度线（每 25m 短线、每 50m 标数字） | 极低 |
| 海床 | 正弦起伏轮廓 + 12 根海草 + emoji 装饰 | 低 |
| 鱼 | 10 种贝塞尔/椭圆组合模板 + 摆尾 + 眼睛 | 中 |
| 光效 | 发光鱼的径向渐变光晕、头灯挖洞、闪白、爆炸环、命中法阵 | 中 |
| 交互反馈 | 震屏、浮动文字、横幅、粒子爆发、11 种音效 | 中 |

**一句话总结原版的美术策略**：*用「渐变色 + 形状 + emoji + 粒子」这套零资源组合，做出了风格统一、辨识度不错的 2D 扁平海底。*
