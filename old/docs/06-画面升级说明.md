## 一、四个目标分别怎么实现的

### 1. 鱼：从「球 + 三角片」到参数化鱼体

原来一条鱼是 7 个独立网格（球体缩放当身体、三角片当鳍、小球当眼），侧面看是椭圆片，鳍是硬边三角。

现在改用**参数化放样**（`src/three/fishgeo.ts`）：

- 沿体长采样 26 段，环向 14 段，横截面为椭圆；
- 体形由一条「半径剖面」数组控制（10 个控制点线性插值），不同鱼种给不同剖面：
  - 纺锤形（鲭鱼/金枪鱼）、细长形（沙丁鱼/鳗）、球形（河豚）、侧扁（比目鱼）、鲨形、大头（鮟鱇）、长吻（独角鲸）；
- 顶点色烘焙「背深腹浅」渐变 + 体侧一条侧线高光，**不再需要贴图**；
- 背鳍/臀鳍是连续弧面（6 段），胸鳍后掠，眼白 + 瞳孔是小球体；
- 尾鳍单独成一个几何，绕尾柄旋转做摆尾。

**关键收益**：一条鱼的 draw call 从 7 降到 2，所以即使几何精细了 3 倍，总 draw call 反而下降。

### 2. 船与渔夫：从「一块砖」到放样船体

原来的船体是 2D 轮廓 `ExtrudeGeometry` 拉伸，侧面就是一块厚板。

现在（`src/three/boat.ts`）：

- **船体放样**：沿船长 34 段，每段算宽度 / 舷高 / 龙骨深度。船首收尖并抬升、船尾平切、截面是带圆角的 U 形，底部有 V 形龙骨；
- 顶点色区分：水线以上船漆、水线一圈浅色、吃水部分深色防污漆；
- 细节件：舷缘、甲板、斜顶驾驶室（三面窗）、舷外机（机头 + 艉杆 + 桨轴）、桅杆 + 航行灯 + 横杆、两只系缆桩 + 缆绳堆、救生圈、鱼箱、水桶、船首护栏；
- 所有静态件合并成 1 个带顶点色的 mesh；
- **渔夫按 7 头身重建**：腿 0.62 + 雨靴 0.24、躯干 0.5、头 0.23，穿救生衣，右臂前伸握竿、左臂下垂；
- 帽子仍是独立 mesh（存档可换装）。

### 3. 水面：玻璃海（折射 + 菲涅尔反射）

原来只是一层半透明渐变，看下去是「一块蓝」。

现在（`src/three/stage.ts` 的 `WATER_FRAG`）：

- **屏幕空间折射**：每帧先隐藏水面，把场景渲染到一张 **半分辨率离屏缓冲**（high 0.6×、mid 0.45×、low 关闭），水面着色器用 `gl_FragCoord / 分辨率` 采样它，并按程序化波形的梯度做 UV 偏移 —— 所以能真的「看穿水面」，水下船体、岩壁、鱼都会被水的波动扭曲；
- **菲涅尔**：视线越平，反射越强；正下方看几乎全透，远处几乎全反射；
- **反射**：解析天空色 + 太阳高光 + 高频干涉碎光（不用立方体反射，省一个 pass）；
- **透明度随视角变化**（0.72 → 0.93），加水体吸收（折射内容偏青蓝）。

为了不出现「水上/水下硬切」，`above` 从布尔值改成 **0~1 连续量**，雾密度、灯光强度、天空球、水面颜色与透明度都按它插值 —— 抛竿入水时相机穿面是渐变的。

### 4. 水下：动态光束 + 焦散

- 原来 9 片静态贴图平面，换成 **14 根着色器光柱**：横向柔边 + 两段不同速度的竖向流动噪声 + 按世界高度衰减；每帧只绕 Y 轴朝向相机（保留横向视差），所以转头时会有「光柱在动」的感觉；
- 岩壁基色压暗（米黄 → 青灰），焦散强度从 0.5 降到 0.26，避免浅水区过曝成白墙；
- 头灯光晕收敛（强度 26 → 13，光晕尺寸上限 4 → 2.2），深水里不再是一个大白球。

### 5. 氛围：一道色彩分级

Bloom 之后加一个全屏 `ShaderPass`：对比度 1.06、饱和度 1.08、暗角 0.42。成本是 1 个全屏 pass，但能让画面「立」起来。

## 二、为什么没直接引现成插件

| 候选 | 否决原因 |
| --- | --- |
| three 官方 `Water`（examples/jsm/objects/Water.js） | 只做平面镜反射，没有折射；且它假设相机始终在水上，与我们的「水上/水下连续穿面」冲突 |
| `Water2` | 依赖 flow map 法线贴图；同样只做贴图混合，反射不到场景里的船 |
| glTF 鱼模型 | 引入外部二进制资源，破坏单文件离线交付；26 种鱼体积不可控 |
| 后处理库（如 postprocessing） | 与现有 `EffectComposer` 管线重复，收益不抵集成成本 |

最终选择：**自写 shader + 程序化几何**。零外部依赖、可随画质降级、所有参数集中在 3 个文件里。

## 三、性能影响（SwiftShader 软件渲染，430×900 @2x）

| 指标 | 优化前 | 优化后 | 说明 |
| --- | --- | --- | --- |
| draw calls（水下） | ~200 | 100~160 | 鱼 7→2、船 9→3，抵掉了光柱增加 |
| draw calls（水上） | ~190 | 120~180 | 多了一次折射 pass |
| 三角形（水下） | 5.2 万 | 7~10 万 | 鱼体几何精细约 3 倍 |
| 额外渲染 pass | 0 | 1（水上，0.6× 分辨率） | 折射 |
| 全屏 shader pass | 0 | 1 | 色彩分级 |
| 帧率 | 8~9 fps | 7~8 fps | 软件光栅化，真机差异较大 |

真实设备上的主要成本是「场景渲染两遍」的顶点与状态切换。按经验预估：中端手机 high 档约掉 15~25%，mid 档（0.45× 折射）约掉 8~12%，low 档（关闭折射、6 根光柱、无 Bloom/阴影）基本持平。

**降级开关**（`stage.ts`）：

| 档位 | 折射 RT | 光柱 | Bloom | 阴影 |
| --- | --- | --- | --- | --- |
| 流畅 low | 关闭 | 6 | 关 | 关 |
| 均衡 mid | 0.45× | 10 | 0.22 | 关 |
| 精美 high | 0.6× | 14 | 0.30 | 1024² |
