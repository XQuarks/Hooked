## 三、关键取舍（一句话版）

**用「固定机位 2.5D」换 3D 光影**：相机永远朝 −Z、只沿 Y 平移，因此碰撞仍是 2D 圆判定、点击仍是平面投影，却能拿到真实的雾、遮挡、体积光和阴影。代价是把 2D 速度整体放慢 30~40%，否则光影来不及被看见。完整论证见 `04-重制方案与关键取舍.md`。

### 4.1 过程中发现并修掉的真实 bug

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 点「开始游戏」直接白屏 + GPU 降级提示 | `new Stage({... onResize: () => this.stage.resize()})` 在构造期回调，`this.stage` 尚未赋值；且即便赋值也会无限递归 | 删除该回调（`engine.ts:186`） |
| 2 | 收线阶段永远浮不出水面，卡到超时 | 坐标约定 y 向下为负，`lure.y += vy*dt` 在 vy<0 时反而继续下沉 | 改为 `lure.y -= vy*dt`（`engine.ts:737`） |
| 3 | 画面整体惨白、深度数字看不见 | Bloom 阈值 0.62 低于天空亮度，整片天空进辉光 | 阈值提到 0.95、强度 0.42→0.30（`stage.ts`） |
| 4 | 水下能看到「天空」，走廊尽头一片黑 | 天空球不参与雾，水面平面只有 120m，远处露出天空/空洞 | 天空着色器加 `uUnder` 水下模式，取当前带水色并随深度变暗；水面色由雾色推导 |
| 5 | 水面上出现巨大的船底挡满屏、岩壁像峡谷 | 船与岩壁在水下仍然可见 | 水下隐藏船、水上隐藏岩壁 |
| 6 | 空中阶段鱼飞出画面，点不到 | 取景用了 `Math.min(top, ...)` 且初值 0，永远不跟随高度 | 改为跟踪最高鱼的 `Math.max`，`target = clamp(top-2.6, -1.2, 9)` |
| 7 | 标题写「图鉴 x/25」而图鉴页写「x/24」 | 分母硬编码，水母不计入 | 统一用 `SPECIES.filter(special!=='jelly').length` |
| 8 | 开局误伤一只水母就罚 $25，等于清空一趟收益 | 罚款下限 25 相对开局收益过高 | 改为 `max(6, 毛收入×10%)` |
| 9 | 第一次出海前打不开手机 | 手机入口只存在于 HUD 的 idle 行，而标题页把它挡住了 | 标题页右上角加「📱 手机」入口 |
| 10 | 长按收线后指针移出按钮，`abortDown` 可能卡住 | 只在按钮元素上复位 | `window` 的 `pointerup` 一并复位（`engine.ts` `onUp`） |

## 五、已知限制

1. **移动端真机未测**。所有验证都在桌面 Chrome 的 headless + SwiftShader 下完成；触屏的「相对拖动」逻辑按移动端习惯实现，但尚未在真机上校准手感（特别是小屏的拖动增益）。
2. **性能未在低端机实测**。桌面软件光栅化下 3 档都能跑；`high` 档在集显手机上可能吃力，建议默认 `mid`。
3. **冰海的洋流、电鳗、冰封鱼**只做了逻辑与单帧验证，缺少「连续 10 趟冰海」的压力测试。
4. **音频**为 WebAudio 实时合成，headless 环境下无法验证听感。
5. **无 i18n**，全中文硬编码。

### 7.2 新的阶段时序（实测）

`cast` 是定时阶段，固定 1.18s 后自动进入 `descent`。`smoke.mjs` 实测（含脚本截图开销，所以 cast 观察值偏长）：

```
cast @0.0s → descent @2.8s → turn @6.0s → ascent @7.5s → shoot @10.6s → idle @16.7s
```

`cast` 内部时间轴：`0~0.2s` 后仰 · `0.2~0.44s` 前甩 · `0.4~0.86s` 抛物线飞行 · `0.86s` 入水（水花 + 全屏水光）· `0.86~1.18s` 相机下沉并淡出到水下。
