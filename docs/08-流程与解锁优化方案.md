# 08 · 流程、剧情节奏与解锁链路优化方案

> **概述**：不改玩法数值、不改美术，只重排「玩家在什么时机、以什么强度、收到什么信息」。核心结论：现在的剧情**写得不差，但投递方式有问题**——87% 的叙事藏在手机红点里，而强制弹层又集中在最不该集中的开场。
> **状态**：**已实施**（2026-10-19）。第七节的 P0~P3 全部落地；实际实现与方案的差异、验证结果见第九节。
> **读者**：决策者（看第一、二、六节）、实施者（看第三、四、五节）。
> **关联**：`07-2D重制说明.md`（渲染层）、`rebuild/src/game/story.ts`（事件表）、`rebuild/src/game/state.ts`（解锁判定）。

先把当前版本跑一遍，按「局数 × 强弹层 × 静默消息」记账。数据来自 `story.ts` 事件条件与 `App.tsx:270` 的弹出时机。

| 时机 | 强制弹层（阻断操作） | 静默进手机 | 玩家感受 |

## 二、痛点

### P1 · 开场三个弹层，玩家 3 分半内没碰过鱼竿
`intro` 事件一次性塞了 `comic → call → notice`。虽然三者内容都不错（漫画讲世界观和玩法，电话交代 NPC 和升级，公告立规矩），但**玩家在零体验的状态下被要求读 3 分半**，这是留存最脆弱的位置。

> 反例是它自己的第 6 格：漫画已经把「下潜躲鱼 → 收线撞鱼 → 空中射击」讲完了。后面的电话和公告**并不承担理解玩法的职责**。

### P2 · 87% 的叙事投递失败
短信和鱼博只增加 `unread` 红点。手机图标上是一个累计数字（现在是 8 个 tab 加起来的和），玩家看到「📱 7」并不知道是主线还是烂梗。

实际后果：
- 未知号码的悬疑线（`d60` 两条「……深一点……」）**是整个故事最好的钩子**，但它躺在短信列表底部，和「老妈让你别宅家」混在一起。
- `money400` 那条「鱼线该升级了」出现在玩家最需要指引的时刻，却只值一个红点。

### P3 · 冰海来电只来一次，且时机不对
`unlockReady` 的触发条件是 `canUnlockIce(s)` = 250m + 11 种。条件满足的**那一刻**播爷爷来电，说「去航线买 2400 的票」。

问题：
- 玩家此时的钱大概率不到 2400（累计收入刚够点满鱼线）。
- `unlockReady` 进了 `fired`，**永远不会再提醒**。
- 航线 App 里的三行条件（深度 ✅ / 图鉴 ✅ / 船票 ⬜）要玩家主动打开才看得到。

结果：**剧情给了目标，但目标当场无法执行，之后也没有任何回声。**

### P4 · 冰海之前没有「阶段感」
从第 1 局到第 15 局，功能解锁是一条斜线：钱够就买。没有「第二章开始」这种断点。

玩家在第 5~14 局的体验是：同一张图、4 个深度带、14 种鱼，反复。期间唯一的新信息是几条鱼博。**这是全流程最大的空窗。**

### P5 · 购买没有优先级
渔具（5 项）、枪（6 把）、帽子（6 顶）全部一开始就开放，只受钱限制。

但数值上只有**鱼线**是收入乘数（深度→更贵的鱼），其余是体验增益。玩家如果在开局把钱花在帽子或第二把枪上，会卡在浅水，收入上不去，形成负反馈。

现在唯一提到这件事的是 `money400` 短信——一条躺着的红点。

### P6 · 岸边没有「下一步」
`Hud` 在 idle 只显示：钱 / 地图 / 当前枪 / 线长 / 钩容量。**没有目标**。

玩家每次回岸都要自己回忆「我上次想干嘛」。对休闲玩家来说，这就是流失点。

### P7 · 教学与实战脱节
`hints` 系统只有 `descent` 和 `shoot` 两个一次性提示。但真正的规则难点是：

- 撞到鱼会**立刻结束下潜**（很多人以为撞到是好事）
- 收线阶段要**主动撞鱼**（和直觉相反）
- 长按可以提前收线保命

这三条只在漫画第 6 格用一行字提过。

### P8 · 漂流瓶依赖运气，且无引导
`bottle1` 是主线（爷爷的第一封信），但它需要玩家真的在 120m 以下碰到 `b1` 号瓶子。瓶子生成在 ±2.4m 随机 x 位置，HUD 没有任何提示。

玩家可能连续几局错过，整条「找爷爷」的线就断了。

### P9 · 解锁之后没有「到家」的确认感
买了票、切换地图，玩家直接面对一个更黑更深的海。除了一个 notice，没有「你现在该干什么」的指引（比如「先买头灯」）。

## 三、改进方案 A：剧情节奏

原则：**先给体验，再给信息；强弹层只留给「玩家会主动想知道的事」。**

### A1 · 开场拆两段（P1）

| 现状 | 改后 |
| --- | --- |
| 漫画 6 格 → 电话 7 句 → 公告 1 页 | 漫画 6 格 → **直接下钩** |
| 首局开始前 3.5 分钟 | 首局开始前 **约 60 秒** |

把翠花电话 + 镇长公告挪到 `firstTrip`（第 1 局结算后）。理由：
- 电话的核心信息是「升级鱼线」「别打水母」——玩家在第 1 局结束后才真正需要它。
- 公告的核心信息是「水母罚款」——第一局如果误打水母，罚款本身就是更好的老师（金额小，且已经配了罚款通知书）。

**改动**：`story.ts` 的 `intro` 只保留 comic；新增 `introAfterFirst`（cond: `s.trips >= 1 && s.fired.includes('intro')`）承载 call + notice。

**存档兼容**：老存档 `intro` 已 fired，新事件 `introAfterFirst` 条件含 `s.trips >= 1`，会补播一次。可接受（相当于「回看」）。

### A2 · 弹层分级与限流（P2）

给 `QueueItem` 增加 `tier: 'main' | 'side'`：

- `main`：漫画、爷爷/未知号码来电 —— 必须看
- `side`：公告、罚款单、瓶子信 —— 可关闭，且**一局最多弹 1 个**

`App.tsx` 的弹出条件加一条：同一批里 `side` 只在没有 `main` 时出队；若 `queue` 里 side ≥ 2，只弹第一个，其余标记为「稍后」。

**预期**：岸边连续弹层的次数从 3 次（开场）+ 2 次（买票后）降到接近 0。

### A3 · 叙事分流（P2，最高优先级）

三档投递：

| 档 | 内容 | 形式 |
| --- | --- | --- |
| 强 | 漫画 / 主线来电 | 全屏弹层（现有） |
| 中 | 关键短信（未知号码、爷爷、老妈第一次、翠花首次引导） | **结算页底部一行**「📱 未知号码发来 2 条消息 ›」，点击直达该会话 |
| 弱 | 鱼博、烂梗、普通短信 | 红点，但**按 tab 分别计数**（现在是一个总和） |

具体改动：
1. `messages` 增加 `tier` 字段，`story.ts` 里给关键消息标 `key: true`。
2. `ResultSheet` 增加「新消息」区块：本局新增的 key 消息按发送者聚合，最多显示 2 条预览 + 「查看全部」。
3. 手机 icon 的红点改成**只统计 key 消息**，其余用 tab 内的小圆点。

**预期**：被动可见的叙事占比从约 15% 提到 55% 左右，且不会增加强制阅读时间。

### A4 · 主线目标条（P6，成本最低、收益最高）

岸边 HUD 增加一行（`.goal-bar`）：

```
🎯 下一个目标：下潜到 120 米   ▓▓▓▓▓░░░░  83m / 120m
```

目标来源：按顺序取**第一个未触发的主线事件**（`d60 → money400 → d120 → species7 → d200 → goldfish → unlockReady → iceUnlocked → iceTrip1 → ice300 → legend`），把它翻译成一句人话 + 进度。

实现：`state.ts` 新增 `mainGoal(s)`，返回 `{ text, progress, done }`。纯函数，不写存档。

**这一条能同时缓解 P3、P4、P6。**

## 四、改进方案 B：解锁链路

### B1 · 冰海拆成两段（P3、P4）

| 阶段 | 条件 | 触发 | 玩家看到 |
| --- | --- | --- | --- |
| 一 · 听见 | **180m + 图鉴 8 种** | 未知号码来电（新写 3 句） | 航线 App 里冰海从「🔒」变成「❓ 未开放海域」，显示两个待办 |
| 二 · 出发 | **250m + 图鉴 11 种** | 现有爷爷来电 | 航线 App 显示船票 $2400，可购买 |

关键变化：**「剧情开门」和「攒钱」解耦**。玩家在 180m 就知道"北方有个地方"，并且知道差什么；到 250m 时剧情才给具体信息；买票是第三步。

同时给 `unlockReady` 补一条**重复提醒**：`canUnlockIce && money < ticket && !s.unlocked.includes('ice')` 时，每次回岸在目标条上显示「船票还差 $XXX」。

**改动**：`UNLOCK_ICE` 增加 `bookDepth: 180`、`bookSpecies: 8`；新增事件 `iceHint`；`mainGoal` 覆盖船票缺口。

### B2 · 购买优先级（P5）

不做硬性锁（会破坏自由度），做三件软引导：

1. **视觉**：渔具列表里「鱼线」加一枚 `⬆ 收入` 标签——因为它是唯一让其它升级更值的项。
2. **文案**：第一次打开渔具且 `line` 为 0 级时，顶部一行「先把线放长，深处的鱼更值钱」。
3. **节点**：`money400` 从短信升级为**一次性轻提示**（岸边 toast，不阻断）：「翠花：线该升级了 → 渔具」。

### B3 · 首潜教学（P7）

现有 hints 扩展为事件驱动，每条只出现一次：

| 触发 | 提示 |
| --- | --- |
| 第一次进入 descent | 「左右拖动移动鱼钩」 |
| 第一次即将撞鱼（距离 < 1.5m） | 「⚠️ 撞到鱼会结束下潜」 |
| 第一次进入 ascent | 「现在反过来：主动去撞鱼，把它钩上来」 |
| 第一次进入 shoot | 「点鱼开枪；打不死会被打得更高」 |
| 钩满 / 到顶 | 「长按收线可提前结束，保住已钩的鱼」 |

实现：`hints` 已有字段，加 key 即可；「即将撞鱼」需要 engine 每帧判断最近距离，成本低。

### B4 · 漂流瓶引导（P8）

最小改动版：瓶子所在深度，在右侧深度轨（`.rail`）上打一个绿色小点。玩家看得见，但要不要去捡仍由自己决定。

成本：`Hud` 里读 `save` 的瓶子列表（已有 `BOTTLES` 和 `bottlesHave`），算当前地图未捡的瓶子深度，画点。

### B5 · 冰海落地引导（P9）

`iceUnlocked` 之后，`mainGoal` 第一条改为「在冰海下潜 100 米」，并在目标条副行提示「永夜需要头灯 → 渔具」。

## 七、实施顺序（建议）

按「改动小、收益大」排序，每步都能独立验收：

| 序 | 内容 | 工作量 | 收益 |
| --- | --- | --- | --- |
| **P0-1** | A4 主线目标条（`mainGoal` + HUD） | 小 | 最高：解决 P3/P4/P6 |
| **P0-2** | A1 开场拆分 | 小 | 高：直接影响首局留存 |
| **P1-1** | A3 结算页新消息区块 | 中 | 高：叙事送达率 |
| **P1-2** | B1 冰海两段解锁 | 中 | 高：填中段空窗 |
| **P1-3** | A2 弹层分级限流 | 小 | 中：节奏顺滑 |
| **P2-1** | B3 首潜教学 hints | 中 | 中：降低首次困惑 |
| **P2-2** | B2 购买优先级引导 | 小 | 中：避免早期误投资 |
| **P2-3** | B4 瓶子 rail 标记 | 小 | 中：防主线断裂 |
| **P3** | B5 冰海落地引导 | 小 | 低 |

建议**先做 P0-1 和 P0-2**，跑一轮回归看手感，再决定后面要不要全做。

## 八、不做的事（避免过度设计）

- **不加新地图、不加新鱼种**：这次只改「已有内容的投放」，不扩内容。扩内容属于另一个议题。
- **不做每日任务/签到**：和这个游戏的叙事调性不搭，且会稀释主线。
- **不改经济曲线**：一旦动鱼价/升级价，所有节奏估算都要重算，风险不可控。
- **不做强制新手关**：教学用 hints 渐进出现，不单独做一个「教学局」。
- **不重写剧情文本**：现有文案质量足够，只改时机与呈现。

| 位置 | 规则 |

## 十、灵动岛通知（2026-10-19 追加）

### 10.1 为什么改

上一版把「来电」和「公告」都做成了全屏弹层：玩家刚想再来一局，就被摁住读七句电话。**强剧情需要存在感，但不需要打断权。**

改成 iOS 灵动岛式的顶部通知：强剧情出一个常驻卡片，你什么时候想接再接；弱消息闪一下就走。

### 10.2 三档强度

| 类型 | 形态 | 行为 |
| --- | --- | --- |
| **来电**（call） | 344×64 圆角卡片，头像 + 名字 + 红绿两键 | **常驻**，不接不走；拒绝后收成胶囊，5 秒后自动再弹 |
| **公告**（notice） | 同上，📢 标识 | 展开 8 秒后收成 182×36 胶囊，点一下还能再打开 |
| **短信**（sms） | 头像 + 发送者 + 内容预览 | **4.5 秒后自动消失**，底部有一条走完就消失的进度线 |

### 10.3 优先级与排队

岛一次只显示一条，优先级：**来电 > 短信 > 公告**。

- 来电常驻，所以短信要能压过「已收起的公告」，否则永远轮不到它亮那 4 秒；
- 短信有 30 秒排队窗口（expireAt）：被来电挡住时，接完电话还能看到；超过 30 秒没轮到就丢弃（红点还在手机里）；
- 公告被短信临时顶掉后会重新展开 8 秒。

### 10.4 全屏弹层还剩什么

只有两类，因为它们本质是「阅读」而不是「通知」：

- **漫画**（序章 / 凯文 / 北极 / 结局）
- **漂流瓶信**

来电、公告、短信全部走岛。这样玩家在钓鱼过程中**任何通知都不会把画面切走**——接听才会暂停并全屏。

### 10.5 其他细节

- 岛展开时，顶部 HUD（钱 / 地图 / 枪 / 线 / 热门鱼）淡出下移，让出位置；收起后自动恢复
- 深度数字下移（2% → 8.5%）、深度轨收窄（top 12%），避免被岛压住
- 短信点一下：岸边直接打开手机短信页；钓鱼中只提示「已收进手机，回岸再看」
- 公告点一下：全屏展开（可随时关闭）
- 支持 prefers-reduced-motion：关闭缩放与呼吸动画

### 10.6 验证

| 用例 | 结果 |
| --- | --- |
| 首局后 | 岛显示「翠花姐 · 📞 来电」（344×64），不打断 |
| 点接听 | 岛让位，全屏通话；结束后自动回到岛 |
| 通话结束 | 岛显示短信「老妈 · 新消息」，4.5 秒后交给公告 |
| 公告 9 秒后 | 收成 182×36 胶囊，显示「点开」 |
| 开场 | 仍然只有 1 个全屏（漫画） |
| 回归 | smoke / flow / check / island / first / sms 六套，控制台错误 0 |

### 10.7 遗留（已在第十一节全部处理）

- 岛内不支持滑动关闭（iOS 那种上滑），只做了拒绝 / 等待消失
- 多条短信只能一条条播，最多同时排队 2 条
- 没有做「未接来电」的持久列表——拒绝后只在岛上重试，手机里没有通话记录

### 11.2 强制来电时的界面

### 11.3 同时补齐的 6 项遗留

## 十二、通知栏与强制来电持久化（2026-10-20 追加）

### 12.1 先修了一个真 bug：点通知 = 开始钓鱼

`.island` 是 `<div role="button">`，而 `tapToCast` 的排除选择器只写了 `button, a, input, .phone, ...`——**没有 `.island`**。
于是点岛上的短信/公告时，`pointerdown` 冒泡到 `.stage`，判定为「点空白处」，直接开始一局。

修复：把 `.island` 加进排除列表。现在点通知只会走通知自己的逻辑。

同时改了点击行为：

| 元素 | 点击后 |
| --- | --- |
| 短信卡片 | **一步**进手机短信（原来要先点展开、再点一次） |
| 公告卡片 | **一步**进手机通知栏，并展开对应的那条公告 |
| 来电卡片 | 展开后接听（强制来电直接接听） |

### 12.2 手机通知栏

状态栏右上角新加了一个 🔔 入口，进去是「通知」页：

```
┌ 通知 ─────────────── 12 条 ┐
│ 📢 关于本人金鱼的声明  公告 │  ← 点一下展开全文
│ 📵 翠花姐        未接来电 │  ← 点一下进短信会话
│ 💬 未知号码          新消息 │  ← 点一下进短信会话
│ 📲 新应用：渔具      系统通知│
└──────────────────────────┘
```

- 数据来源：`SaveState.notices`（公告/系统通知留档）、`calls`（只列未接）、`messages`
- 按 `trip` 倒序排列，同一趟保持写入顺序
- 公告点击就地展开/收起；消息和未接来电直接跳进对应会话（`onJump('sms', thread)`）
- 岛上的公告 22 秒后会自动让位，但**通知栏里的记录不会消失**

新增字段 `notices: NoticeRecord[]`，老存档由 `loadSave` 的默认值兜底（`notices: []`）。

### 12.3 强制来电：不做超时，只做持久化

按你的要求：不加「超时未接」，改为**关掉游戏、切后台、刷新页面回来，仍然是那通等待接听的电话**。

三处改动：

1. **接听时不删队列**：`openStory` 只负责打开通话界面；只有通话真正结束（`挂断` / 走完最后一句）才把队列项移除并记「已接」。
   → 通话中途刷新，队列里还有这通电话，重进游戏会重新出现。
2. **切后台不叠暂停面板**：`visibilitychange` 检测到有强制来电时直接返回。
   之前会把暂停面板（音效/画质/回到岸边）盖在来电上，回来就看不到电话了。
3. **进游戏自动冻结**：`forcedUid` 变化时立即 `setPaused(true)`，并把 React 的暂停面板关掉。

实测（`persist.mjs`）：

| 动作 | 结果 |
| --- | --- |
| 强制来电 | `island.force` + 幕布，HUD 隐藏，无暂停面板 |
| 切后台 | 面板不出现，状态不变 |
| 通话中刷新页面 | 回来仍是 `island.force`「海底的瓶子」 |
| 接完 | 队列清空，`calls` 记一笔 `missed:false` |

### 12.4 又修了一个真 bug：类名撞车

通知行最初写成 `class="ntf notice"`，结果被全屏公告的 `.notice { position: absolute; inset: 0 }` 捕获——
9 条通知全部绝对定位叠在一起，整页看起来像被高斯模糊了。

改成 `.ntf.kind-notice / kind-sms / kind-call / kind-sys`，与 `.notice` / `.call` 彻底隔离。
（教训：全局样式项目里，组件内类名不要用 `notice` `call` `sheet` 这种通用词。）

- 通知栏没有「全部已读」和一键清空

## 十三、界面整理与 App 拆分（2026-10-20 追加）

### 13.1 短信红点不消失——两处都漏了

红点是两套字段：`unread`（全部未读）和 `unreadKey`（主线未读）。手机图标只读后者。

- `SmsApp` 切 tab 时只清了 `unread`，没清 `unreadKey`；
- 更关键的是：只有「从主屏幕点图标」才会走 `openApp` 清红点。从**灵动岛**或**结算页**直接进短信时，`app` 是初始值，`openApp` 根本没执行，两个字段都是原值。

修复：

1. `Phone` 里加了 `useEffect([app])`——只要进入任何 App，就清掉 `APP_BADGES[app]` 对应的 `unread` 与 `unreadKey`，与入口无关；
2. `openApp` 只负责 `appsSeen`（NEW 标），不再兼任清红点。

### 14.1 天气系统

天气不是一行文字，它同时改「看起来」和「钓得到什么」。

**数据**（`src/game/data.ts`）：

### 14.3 命中反馈

原来有两个缩放 bug，都源于把「倍率」当成了「米数」：


- `AirFish` 增加 `baseScale`（出水时统一 1）与 `hits`（挨枪数）

| 震屏 | +4.3 | +5.4 |

## 十五、击杀消失与水面衔接（2026-10-20）

### 15.1 被击杀的鱼当场消失

原来的死亡流程是「状态改死 → 0.8 秒缩小淡出 → 回收」。问题在于缩小那一下很像「鱼变小了还在飞」，
玩家分不清是打死了还是打偏了，打击感反而变钝。

现在 `damage()` 的击杀分支直接 `factory.release(mesh)` 并把状态置 `lost`，鱼体在命中的那一帧就没了，
只留爆开的碎光、冲击环和 `+$` 飘字。`AirFish.state` 里的 `dead` 一并删除，`updateShoot` 不再有死亡过渡分支。

顺带改了 HUD 的总额：

```
旧：$ estimate + airValue          // 打死一条，总额立刻掉下去
新：$ gross + estimate + airValue  // 打死的钱已入账，数字只涨不跌
```

`HudState` 因此多了一个 `gross` 字段。

### 15.2 水面不再是布尔开关

这是「衔接不流畅」的根因。原来 `above` 是按阶段给的 0/1：`idle`/`shoot` 是 1，
`cast` 期间靠 `castBlend` 从 1 渐变到 0，`descent`→`ascent` 一律是 0。而背景层用
`above > 0.55` 二选一：要么画天空 + 海面，要么画水体。**所以穿越水面必然是「啪」地换一张图。**

改成三层：

| 层 | 做法 |
| --- | --- |
| 判据 | `above` 由镜头高度连续换算：`clamp(0.5 + camY / 4, 0, 1)`，水面上下各 2 米是过渡带 |
| 背景 | 水体永远铺底；天空只画在**水线以上**那一条（`clip(0, 0, W, screenY(0))`），透明度 = `above` |
| 水面 | `seaSurface` 的波纹、反光、亮带跟着水线走，透明度同样 = `above` |

于是镜头下沉时，水线在屏幕上向上滑、天空一点点透成水色；上浮时反过来。
**水下抬头能看到头顶那层水面**，是几何上真实发生的，不是切图。

`setCamera` 里原来那句 `cam.cy = focusY + CAM_LEAD + above * 0.9` 删掉了——`above` 现在由 `camY` 反推，
再加高度会形成「镜头动 → above 变 → 镜头再动」的反馈抖动。

`paintFront` 的近景水草也加了 `clip`，只画在水线以下；否则镜头贴着水面时水草会飘到天上。

### 15.3 镜头：入水跟着钩子，出水提前抬起来

| 段 | 之前 | 现在 |
| --- | --- | --- |
| 抛竿入水 | 钩子还在空中 0.3m，镜头已经追到水下 3.4m（看着像穿模） | `camOffset(depth) = 1.2 + min(1, depth/6) × 2.2`，镜头与钩子同步下沉，偏移量随深度慢慢拉开 |
| 咬钩 → 收线 | `turn` 跟 `lure.y + 0.6`，`ascent` 跟 `lure.y + 3.1`，切相位时镜头跳 2.5m | 两段统一成 `lure.y + 3.1`，`turn` 用更软的 `k=4` 摇下去 |
| 收线出水 | 出水瞬间 `above` 从 0 跳到 1 | 钩子出水前 2 米天空就已经恢复（镜头先出水），鱼再冲出来 |
| 空中视角 | `target` 下探到 `-1.2`，镜头会掉到水下 | 下限提到 `0.4`，始终在海面之上 |
| 鱼的初速 | 固定 `17~22` | 继承收线速度：`max(17, min(25, |lureVy| × 0.92 + 3))`，收得越快甩得越高 |

## 十七、命中溅汁与空中镜头修正（2026-10-21）

### 17.1 钩到水母时，镜头不再怼着它

空中相机原来是「跟最低的那条鱼」。这条规则对能卖钱的鱼是对的——它最快落回水里、最该先打。
但水母是扣钱的（`value: -25 / -55`），把它钩上来甩上天本来就是失误，镜头凑过去等于把失误摆在画面正中，
还挡住了真正该打的鱼。

改法只有一行过滤：

```ts
for (const a of this.air) {
  if (a.state !== 'fly') continue;
  if (a.sp.value < 0) continue;   // ← 扣钱的鱼不参与取景
  ...
}
// 天上全是扣钱鱼时，回到水面附近，让它们自己在画面上方飞走
if (!Number.isFinite(low)) { low = 1; lowVy = 0; lowX = 0; }
```

实测：水母在左下（x=-2.6）、能卖钱的在右上（x=2.1）时，`camX = 1.91`（贴右边那条）；
把天上所有鱼都改成 `value=-25` 后，`camX = 0.01`、`focusY = -0.04`（回水面）。

### 17.2 击中溅汁（参考《我只是水果》）

原来命中只有「鱼闪白 + 一圈冲击环 + 飘字」。现在加了一套「爆汁」：

| 层 | 做法 |
| --- | --- |
| 色斑 `splat` | 命中点一团鱼色的径向渐变，0.15 秒内膨胀 + 淡出，负责「爆开」的第一眼 |
| 汁液 `juice` | 16~32 颗液滴，普通混合（不是加色），沿锥形喷出，重力 -22，**沿速度拉长** |
| 描边 + 高光 | 每颗液滴「深色描边 + 暗部主体 + 亮部高光」，浅色天空上也读得出来 |
| 载体速度 | 液滴初速 = 喷射速度 + 鱼被顶飞的速度 × 0.8，所以是「从鱼身上甩出去的」而不是掉在原地 |

配色上踩了两个坑，最后定的是**亮部与暗部的中点**（`mix(color, color2, 0.5)`）：
纯亮色（沙丁鱼的 #b9cfe0）在浅蓝天上几乎隐形；纯暗色又像墨汁。

### 17.3 顺带发现：整层特效从来没有被渲染

这是本次最严重的发现。`FX`（粒子 / 冲击环 / 飘字）从 2D 重构时就存在，engine 每帧 `fx.update(dt)` 也在跑，
但 `stage2d.ts` 的 `render()` 里**始终没有调用 `fx.draw()`** ——
所有粒子、所有 `+$`、所有「击飞!」都只存在于内存里，然后过期消失。

所以之前调的所有「打击感」参数，玩家一个都没看到过。修复：

```ts
// stage2d.render()
this.backdrop.paintFront(...);
weatherParticles(...);
this.fx?.draw(g, cam);   // ← 补上这一行
```

接上之后画面一下子「满了」，原来那套尺寸（火星 size 0.34、冲击环半径 2.15m）会糊成一团白光，
于是把粒子整体压小、命中不再画冲击环（跟着鱼飞像肥皂泡），只保留汁液当主角。

### 17.4 两个配色 bug

1. `shade()` / `mixHex()` 返回的是 `rgb(...)` 字符串，而 `rgba()` 只解析 `#rrggbb`。
   传进去会得到 `rgba(NaN,NaN,NaN,a)`，canvas 直接忽略 → **整个粒子层隐形**。
   在 `fx2d.ts` 里自己写了 `rgbOf / hexOf / darken / lighten / mix`，统一进出 hex。
2. 命中时用的加色粒子（`lighter`）会把鱼色冲成白色，汁液看不出颜色。
   现在汁液走 `source-over`，只有火星和白光走加色。

## 十八、系统通知不再重复弹、收起的胶囊可点（2026-10-22）

用户反馈两件事：「解锁鱼博」反复弹；收起后的系统通知点了没反应。

### 18.1 反复弹的根因：岛被卸载，计时器一起没了

`App` 里只要 `islandItem` 为 null（开手机、结算页、出海、标题页）就整块不渲染 `<Island>`。
React 卸载会走 `useEffect` 的 cleanup，`clearTimers()` 把 6s 收起 / 20s 消失两个 `setTimeout` 全清掉。
结果：只要玩家在 20 秒内开关一次手机或出一次海，公告就永远死不掉，回来重新挂载 → `expanded` 重置为 true → **又整块弹一次**。

改法：

- `islandItem` 为 null 但条目还在队列里时，`<Island hidden>` **继续挂载**，只加 `.is-hidden` 淡出；
- 计时改成**绝对死线**（`deadlines.collapse / dismiss`），隐藏时记下时刻、露出来时把停掉的时长补回去；
- 隐藏时顺手 `setExpanded(false)`，所以回来看到的是小胶囊，不是又一次整块弹开（来电除外，它本来就不该自己收起）。

### 18.2 点了没反应的根因：系统通知根本不在剧情队列里

`openNotice(uid)` 第一句是 `save.queue.find(x => x.uid === uid)`，
而「新应用解锁」的 uid 是 `app_<appId>`，是由 `appUnlocked()` 现算出来的，**不在 queue 里** → `if (!it) return` 直接返回，连 `sfx` 都不响。

改法：`app_` 前缀单独走一条分支，直接进手机通知栏；存档里的通知 id 是 `sys_<appId>`，用它作为 `focus` 让那一条自动展开。
批量解锁（`app_batch_*`）没有单一 focus，就只打开通知列表。

### 18.3 顺手减少噪音

| 项 | 之前 | 现在 |
|---|---|---|
| 一次解锁 2 个 App | 连弹两条 | 合并成「新应用 ×2：鱼博、渔具」 |
| 公告展开时长 | 8s | 6s |
| 公告总寿命 | 22s | 20s |
| 关闭方式 | 只能上滑 | 展开时右上角有 ✕，上滑仍然可用 |
| 位置 | 顶部正中，和金币 / 武器 chip 挤同一行，展开时要把 HUD 整块淡掉 | 下移到 chip 下方（safe area + 104px），HUD 不再让位，也不挡任何可点区域 |

用「把剧情 `fired` 填满、`trips=0`」的存档结算一局，稳定触发鱼博 + 渔具同时解锁：
